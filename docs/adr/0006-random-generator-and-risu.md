# ADR 0006 — Random programs for M1 generated in Rust; RISU from M2

- Status: accepted (M1, 2026-09-24). Changes the M1 exit criterion.

## Context
For M1, the plan calls for 200 random programs generated by RISU with final
registers equal to `qemu-aarch64`. RISU, however, is not just a generator: its
harness (`risu`) is a C program that runs the test block and compares
the state inside a SIGILL handler with `ucontext`. Running it as
"apprentice" inside Vetro requires signals, syscalls and a complete Linux
binary: that is M2 work.

## Decision
- In M1 the random programs are generated by `vetro-diff::random`, on the same
  principle as RISU: random bits inside the masks of the integer instruction
  classes (not starting from our decoder), fields corrected only
  where needed (reserved registers, valid addresses, forward branches),
  CONSTRAINED UNPREDICTABLE cases excluded.
- Each program: a prologue that sets random registers and flags, a random
  body, an epilogue that writes x0–x30, SP, NZCV and the memory block
  to stdout. Vetro's output and QEMU's are compared byte for byte.
- In a share of the programs the body ends with an instruction that
  our decoder declares UNDEFINED: QEMU must die of SIGILL at the same
  point. This way decoder errors in the "too restrictive" sense also
  surface.
- Deterministic and reproducible seeds (`VETRO_DIFF_SEED`), configurable number
  of cases (`VETRO_DIFF_CASES`, default 250; many more at night).
- Real RISU comes in M2, when Vetro runs Linux binaries with signals.

## New M1 exit criterion
Per-instruction suite green (expected values also verified against QEMU) and
at least 200 random programs from `vetro-diff::random` identical to
`qemu-aarch64 -cpu cortex-a53`, with `VETRO_REQUIRE_ORACLE=1`.

## Update (M2, 2026-09-24)
RISU is integrated: `tools/risu/build.sh` builds `risu` (musl, static),
generates ARMv8.0 images with `risugen` (v8.1+ patterns excluded) and records
the traces with `qemu-aarch64 -cpu cortex-a53` as master;
`tests/linux/tests/risu.rs` runs `risu` on Vetro as apprentice. The
first run found a decoder bug (vector logical ops with size = 11 and
Q = 0 rejected) that the M1 generator did not see. Linaro's official
repository was not responding: we use Richard Henderson's fork, at a pinned
commit.
