# Spec — boot from Android images (`vetro_machine::android`)

## Scope
The work of the Android bootloader in front of the M3 Linux loader
(`vetro_machine::boot`, ADR 0008): from `boot.img`, `vendor_boot.img` and
`init_boot.img` to an uncompressed arm64 `Image`, an initrd and a command
line, which then follow the `-kernel/-initrd/-append` path (QEMU
layout, DTB generated by Vetro). Pure module: no files, no guest
memory; compiles for wasm32 too. Decisions: ADR 0018.

Reference formats: AOSP `system/tools/mkbootimg` (`bootimg.h`,
`mkbootimg.py`; pinned copy in `tools/mkbootimg/`), source.android.com
(Boot image header, Vendor boot partitions, Implement bootconfig), the
kernel's `Documentation/admin-guide/bootconfig.rst`.

## Formats read
| Image | Versions | Page | Sections (each aligned to the page) |
|---|---|---|---|
| `boot.img` | 0, 1, 2 | from the header (2–16 KiB) | header, kernel, ramdisk, second, recovery_dtbo (v1+, offset from the header), dtb (v2) |
| `boot.img` | 3, 4 | 4096 fixed | header, kernel, ramdisk, GKI signature (v4) |
| `init_boot.img` | 4 | 4096 | header, ramdisk (empty kernel, mandatory) |
| `vendor_boot.img` | 3 | from the header | header (2112 bytes), vendor ramdisk, dtb |
| `vendor_boot.img` | 4 | from the header | header (2128 bytes), ramdisk (concatenated fragments), dtb, ramdisk table (108-byte entries), bootconfig |

`boot.img` command line: v0–v2 `cmdline` (512) followed without a
separator by `extra_cmdline` (1024), like `unpack_bootimg.py`
(mkbootimg splits a long line at 511 bytes); v3/v4 a single 1536-byte field.

Ignored (not needed for virt): load and tag addresses,
`second`, `recovery_dtbo`, the DTBs (`boot` v2 and vendor: Vetro generates its own),
the GKI signature, `board_id` (read and exposed, not used for selection).

## Public interface
- `BootImage::parse(&[u8])`, `BootImage::parse_init_boot(&[u8])`:
  sections as slices of the image, `cmdline`, `name`, `os_version`
  (`OsVersion`: version and patch level), `header_version`,
  `page_size`.
- `VendorBoot::parse(&[u8])`: `cmdline`, `name`, `ramdisk_section`,
  `ramdisks: Vec<VendorRamdisk>` (`kind: RamdiskType`, `name`, `board_id`,
  `data`; v3 has a single unnamed `Platform` ramdisk), `dtb`,
  `bootconfig`.
- `assemble(&BootImage, Option<&VendorBoot>, Option<&BootImage>, &BootOptions)
  -> Result<AndroidBoot, AndroidError>`; `AndroidBoot::from_images(boot,
  vendor_boot, init_boot, opts)` reads and combines.
- `BootOptions { params: String, recovery: bool }`: parameters added by the
  bootloader (command-line syntax) and boot into recovery.
- `AndroidBoot { kernel, kernel_format, initrd, cmdline, bootconfig, ramdisks }`,
  `initrd() -> Option<&[u8]>`.
- `Machine::load_android(&AndroidBoot)` = `load_linux(kernel, initrd, cmdline)`.
- `android::decompress`: `detect`, `decompress` (`Image` as is, gzip,
  legacy LZ4, LZ4 frame), `gunzip`, `inflate`, `lz4_legacy`, `lz4_frame`,
  `lz4_block`, `crc32`. Maximum output 512 MiB.
- `android::bootconfig`: `append(initrd, text)`, `split(initrd)` (the
  reverse, like the kernel), `checksum`, `split_cmdline`, `key_value`,
  `param_line`.
- Errors: `AndroidError` (truncated, magic, version, page, section outside
  the image, ramdisk table, invalid `init_boot`, incompatible
  images, missing or non-decompressible kernel, bootconfig,
  loader `BootError`).

## Bootloader rules (invariants)
1. **Kernel:** recognised from its first bytes; gzip checks the CRC32 and
   length of every member; legacy LZ4 (`lz4 -l`, independent blocks,
   concatenated streams) and frame (linked blocks, xxHash checksums not
   verified). Unknown format: error.
2. **Initrd:** vendor ramdisks in table order, without those
   of type `Recovery` unless `recovery: true`, then the generic ramdisk
   (`init_boot` if given, otherwise `boot`), joined with no gaps or
   alignment. Ramdisks are not decompressed: the kernel opens them, so
   an LZ4 stream can only be followed by another LZ4 stream (as
   AOSP requires: vendor and generic in the same format).
3. **Command line:** `boot`, then `vendor_boot`, then the parameters of
   `BootOptions::params` that do not go into the bootconfig, separated by a
   space.
4. **Bootconfig** (only with `vendor_boot` v4): text = the vendor's bootconfig
   section (without trailing NULs, with a trailing `\n` added if missing) followed
   by a `key = "value"` line for every `androidboot.*` in
   `BootOptions::params` (single quotes if the value has double quotes; a key
   repeated in the parameters = error). A parameter with the key of a line of the
   vendor section replaces that line in place instead of being appended
   (ADR 0028: repeated, the kernel would discard the whole block). If the
   text is not empty: block
   `text, NUL, NUL padding up to an initrd that is a multiple of 4, size (le32),
   checksum (le32, sum of the bytes), "#BOOTCONFIG\n"` appended to the initrd
   (identical to the kernel's `tools/bootconfig -a`), and `bootconfig` added
   to the command line if not already there. Maximum 32767 bytes (`XBC_DATA_MAX`).
   `androidboot.*` already in the images' command lines stay there.
5. Without `vendor_boot` v4 (v3, v0–v2, or `boot` alone) the
   `androidboot.*` parameters go on the command line.
6. Rejected combinations: `vendor_boot` with `boot` v0–v2, `init_boot` with
   `boot` before v4, `init_boot` with a kernel or before v4.

## CLI
`vetro boot --boot-img FILE [--vendor-boot FILE] [--init-boot FILE]
[--recovery] [--append LINE] [--android-dump DIR]`: `--append` becomes
`BootOptions::params`; `--android-dump` writes `Image`, `initrd` and
`cmdline` as the kernel receives them (the same files for
`qemu-system-aarch64 -kernel -initrd -append`). All `boot` options that
take a value accept `--option=value` and `--option value`.

## Guest kernel
`guest/kernel/config/vetro.config` has `CONFIG_BOOT_CONFIG=y` (without
`FORCE`, like the GKI: the block is used only with `bootconfig` on the command
line) and `CONFIG_RD_LZ4=y` (the GKI's legacy LZ4 ramdisk).

## Tests
- `android::tests`, `android::bootconfig::tests` (unit): real `gzip`
  and `lz4` vectors, round trip with the system tools if
  present, the guest's real initramfs, block bytes equal to those of
  `tools/bootconfig -a` from kernel 6.18.53, rules 2–6, errors.
- `crates/vetro-machine/tests/mkbootimg.rs`: images from `mkbootimg.py`
  (v0, v1, v2 with 2, 4 and 16 KiB pages and a split command line; v3
  with vendor v3; v4 with three fragments, board id, bootconfig and
  `init_boot`): every section read equal to the given file. Needs `python3`
  (`VETRO_REQUIRE_ORACLE=1` makes it mandatory).
- `tests/boot/tests/android.rs` (release): guest kernel in `boot.img` v4
  (gzip), initramfs in `init_boot` (legacy LZ4), three vendor fragments
  (cpio, recovery, LZ4 with an `/init` to shadow), vendor and
  bootloader bootconfig. The guest sees the expected `/proc/cmdline` and
  `/proc/bootconfig` and the right files under Vetro and under QEMU
  (`-kernel/-initrd/-append` with the same unpacking); the two logs match except for
  `KNOWN_DIFFERENCES`.
- `crates/vetro-cli/tests/boot_android.rs` (release): `vetro boot
  --boot-img --vendor-boot --android-dump` with the options in the
  space-separated form.
