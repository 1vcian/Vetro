# Spec — the Vetro AOSP image (`guest/aosp`, `tools/aosp`)

Decisions: ADR 0022; development CA, branding and build: ADR 0030. Research: `docs/research/m5-android-images.md`,
`docs/research/m5-gki-boot.md`. Bootloader: ADR 0018,
`docs/specs/android-boot.md`.

## Scope
A 64-bit-only AOSP 15 arm64 image, product `vetro_arm64`
(`vetro_arm64-bp1a-userdebug`, tag `android-15.0.0_r36`), that boots on the
virt machine of Vetro and of QEMU (`-M virt,gic-version=3,its=off -cpu
cortex-a53 -smp 1 -m 3G`, virtio-mmio) with the prebuilt GKI android15-6.6
kernel and the Vetro bootloader, and ships microG. Build on the dedicated
x86_64 Linux VM; boot tests under QEMU on the same VM (`tools/aosp/qemu-vm.sh`)
and under Vetro.

## Files
| Path | Content |
|---|---|
| `guest/aosp/device/vetro/vetro_arm64/` | product (`vetro_arm64.mk`, `AndroidProducts.mk`, `PRODUCT_SYSTEM_*`), board (`BoardConfig.mk`: first-stage modules, bootconfig, empty host cross), `device.mk`, `fstab.vetro`, `init.vetro.rc`, `modules.blocklist`, `sepolicy/`, `vetro-files/` (Android.bp and rc; the `.c` comes from `guest/kernel/initramfs`), `overlay/` (RRO `VetroFrameworkOverlay`, `VetroPackageInstallerOverlay`, `VetroBrowserOverlay`, `VetroSettingsOverlay`), `branding/wallpaper.png` (from `tools/aosp/wallpaper.py`) |
| `guest/aosp/vendor/vetro/microg/` | `microg.lock` (file, sha256, release URL), modules `VetroGmsCore`/`VetroGmsCompanion`, privileged-permission allowlist, default permissions, sysconfig |
| `guest/aosp/vendor/vetro/dev-ca/vetro-dev-ca.pem` | development CA certificate (EC P-256, `79e94fc0.0`); the private key is in `~/.config/vetro/dev-ca/vetro-dev-ca.key`, never in the repository |
| `guest/aosp/patches/<project>/NNNN-*.patch` | patches to the AOSP tree: `frameworks/base` (signature spoofing limited to microG), `external/conscrypt` and `system/ca-certificates` (development CA in the trust stores, generated by `tools/aosp/dev-ca.sh`), `device/generic/goldfish-opengl` (ranchu HWC: BGRA frame and cleared device composition, ADR 0032) |
| `tools/aosp/` | scripts run from the Mac: `sync.sh`, `build.sh`, `fetch.sh`, `mkdisk.sh`, `qemu.sh`, `vetro.sh`, `upload.sh`, `gpl-sources.sh`, `dev-ca.sh`, `wallpaper.py`, `qemu-vm.sh` (QEMU on the build VM); `remote/` on the VM: `prepare.sh`, `build.sh`, `pack.sh`, `gpl.sh`, `qemu.sh`, `disk-layout.sh` (the GPT disk, also used by `mkdisk.sh`) |

## Flow
1. `tools/aosp/sync.sh`: `dev-ca.sh check` (certificate and patches
   consistent), rsync of `device/vetro`, `vendor/vetro` (without the
   downloaded prebuilts) and of the `vetro-files` source into the VM's tree,
   patches applied if missing (a patch that does not apply stops everything;
   only the files of the current patches remain in the trust stores), microG
   APKs downloaded and verified against the lock's sha256, Vetro commit in
   `~/vetro-aosp/sync.rev` (`-dirty` with uncommitted changes).
2. `tools/aosp/build.sh start|status|wait`: if no build is already
   running, `sync.sh` then `lunch` + `m droid` detached (nohup/setsid; state in
   `~/vetro-aosp/build.status`: RUNNING, OK, FAIL n; log in `build.log` with
   CPU, RAM, duration and size of `out/host/*`; `build.rev` = the `sync.rev`
   of the successful build). Incremental in `out/`. ccache only with
   `VETRO_AOSP_CCACHE=1` (in `out/.ccache`, the only writable part with the
   tree in the sandbox; the first time it recompiles all the C/C++, ADR 0030).
3. `tools/aosp/fetch.sh`: `remote/pack.sh` checks the result (development
   CA in the conscrypt APEX and in `/system/etc/security/cacerts`,
   overlays, wallpaper, no QuickSearchBox, `ro.config.wallpaper`,
   `ro.product.system.brand=Vetro`), copies the images and the properties,
   writes `build-info.txt` and `SHA256SUMS`; rsync into `target/aosp/out/`,
   hash verification, checks (ART ISA variant `cortex-a53`, no
   32-bit ABI, CA equal to the repository's), then `mkdisk.sh`.
4. `tools/aosp/mkdisk.sh`: `target/aosp/disk.img` (see "Disk").
5. Boot: `tools/aosp/qemu-vm.sh start` (oracle, native QEMU 10 on the build VM
   with the VM's images: heavy runs stay off the Mac; `status`, `log`, `adb`,
   `screendump F.png` = the scanout as QEMU shows it, `screencap F.png` =
   SurfaceFlinger's picture), `tools/aosp/qemu.sh > qemu.log` (same machine in
   Docker on the Mac) and
   `tools/aosp/vetro.sh [guest seconds] > vetro.log`.
6. `tools/aosp/gpl-sources.sh`, then `tools/aosp/upload.sh` (R2).

Variables (`tools/aosp/common.sh`): `VETRO_AOSP_HOST` (default
`target/aosp/vm-host`, then the VM's address), `VETRO_AOSP_KEY`
(`~/.ssh/vetro_aosp`), `VETRO_AOSP_TREE` (`aosp`), `VETRO_AOSP_WORK`
(`vetro-aosp`), `VETRO_AOSP_LUNCH`, `VETRO_AOSP_CCACHE` (0);
`VETRO_DEV_CA_DIR` (`~/.config/vetro/dev-ca`, `dev-ca.sh`). The artefacts
live in `target/aosp` of the checkout the scripts are run from.

## Artefacts (`target/aosp/out/`, never in git)
| File | Content |
|---|---|
| `boot.img` | header v4, GKI kernel (`kernel-6.6`), no ramdisk |
| `init_boot.img` | header v4, generic ramdisk (LZ4) |
| `vendor_boot.img` | header v4: vendor ramdisk (first stage, modules, `fstab.vetro`), vendor command line, bootconfig section |
| `super.img` | sparse: logical partitions of slot A (erofs) |
| `userdata.img` | sparse: empty 8 GiB f2fs |
| `build-info.txt` | `vetro_rev` (Vetro commit of the build), `dev_ca` (development CA file), manifest tag, BUILD_ID, kernel string and build id, vermagic and scmversion of the modules, cuttlefish commit, kernel prebuilts and frameworks/base |
| `props/` | `build.prop` of the partitions, `fstab.vetro`, `modules.load` of the vendor_ramdisk |
| `SHA256SUMS` | sha256 of all files |

## Disk (`target/aosp/disk.img`)
GPT, partitions aligned to 1 MiB, sparse file:
| # | Name | Size | Content |
|---|---|---|---|
| 1 | `misc` | 1 MiB | zeros |
| 2 | `frp` | 1 MiB | zeros |
| 3 | `metadata` | 64 MiB | empty ext4 (`mkfs.ext4 -L metadata`) |
| 4 | `super` | 7 GiB | `super.img` expanded |
| 5 | `userdata` | 8 GiB | `userdata.img` expanded |

The first stage mounts `/metadata` and the logical partitions of `super`
(`/dev/block/by-name/*` from the GPT names, on the devices of
`androidboot.boot_devices`); `/data` is mounted at `mount_all --late`,
encrypted by vold with the key in `/metadata`.

## Machine and devices
Same devices, in the same order, in QEMU and in Vetro (the first goes
into virtio-mmio slot 31, `0x0a003e00`):
| Slot | QEMU | Vetro (`vetro boot`, default) |
|---|---|---|
| 31 | `virtio-gpu-device` (2D) | GPU 1280x800 |
| 30 | `virtio-keyboard-device` | keyboard |
| 29 | `virtio-tablet-device` | tablet |
| 28 | `virtio-net-device` + `-netdev user,hostfwd=tcp::5555-:5555` | network + `--hostfwd=tcp:127.0.0.1:5555-:5555` |
| 27 | `virtio-blk-device` (`disk.img`, `snapshot=on`) | `--disk=disk.img` (copy-on-write in memory) |

With `--vsock` (file manager) Vetro puts vsock in slot 27 and the disk
in 26: `boot_devices` lists them all, so nothing changes. QEMU in
Docker has no vsock.

## Command line and bootconfig
- Command line: that of `boot.img` (empty) + vendor (`printk.devkmsg=on
  audit=1 panic=-1 8250.nr_uarts=1 cma=0 firmware_class.path=/vendor/etc/
  loop.max_part=7 init=/init bootconfig console=ttyAMA0`, from Cuttlefish and
  `BoardConfig.mk`) + `nokaslr` from the scripts (comparable logs).
- Bootconfig (vendor_boot section, `BOARD_BOOTCONFIG`): `hardware=cutf_cvm`,
  `boot_devices` (32 slots), `slot_suffix=_a`, `force_normal_boot=1`,
  `verifiedbootstate=orange`, `fstab_suffix=vetro`, `console=ttyAMA0`,
  `serialconsole=1`, graphics (`cpuvulkan.version=4202496`,
  `hardware.gralloc=minigbm`, `hardware.hwcomposer=ranchu`,
  `display_finder_mode=drm`, `display_framebuffer_format=bgra` (the HWC
  converts its frame to BGRA: virtio-gpu 2D resources are B8G8R8X8, ADR 0032),
  `hardware.egl=angle`, `hardware.vulkan=pastel`,
  `opengles.version=196609`, ranchu composer APEX, `lcd_density=240`),
  software KeyMint and Gatekeeper, `serialno=VETRO00001`, `ddr_size=3072MB`,
  `setupwizard_mode=DISABLED`, `enable_bootanimation=0`,
  `hw_timeout_multiplier=50`, `hypervisor.*=0`, `selinux=permissive`.
- The Vetro bootloader appends the `androidboot.*` parameters from
  `--append` (ADR 0018): the scripts pass none.

## Checked invariants
- `dalvik.vm.isa.arm64.variant=cortex-a53` and no `abilist32`
  (`fetch.sh`).
- microG APKs with the lock's sha256 (`prepare.sh`), microG certificate
  in the patch (`9bd06727…d14165`, `keytool -printcert -jarfile`).
- Privileged-permission allowlist = the `android.permission.*` permissions of
  the APKs (`aapt2 dump permissions`, to be regenerated with the release).
- `SHA256SUMS` verified at every hop (VM → Mac → R2).
- A version on R2 never changes: `upload.sh` rejects an object with the same
  name and a different sha256, and does not publish an image built from
  uncommitted changes (`vetro_rev` with `-dirty`). Previous versions remain.
- Development CA: `dev-ca.sh check` (patch = certificate, local key =
  certificate), `pack.sh` (in the APEX and in system), `fetch.sh` (`dev_ca` =
  hash of the repository's certificate).
- First boot (ADR 0032, `pack.sh`): `SystemUI`, `Launcher3QuickStep`, `Settings`
  odex with compiler filter `speed`, `pm.dexopt.first-boot=skip`, no `.capex`
  in `/system/apex`, `display_framebuffer_format=bgra` in vendor_boot.
- Branding: overlays and wallpaper installed, no `/product/app/QuickSearchBox`,
  `ro.config.wallpaper`, `ro.product.system.brand=Vetro` (`pack.sh`: the four
  overlays `VetroFrameworkOverlay`, `VetroPackageInstallerOverlay`,
  `VetroBrowserOverlay`, `VetroSettingsOverlay`).

## Branding (ADR 0030)
| What | How |
|---|---|
| "Google" bar on the home screen | QuickSearchBox not installed (`overrides` of `VetroFrameworkOverlay`): Launcher3 shows the neutral "Search" bar |
| icon of apps without an icon | RRO `VetroFrameworkOverlay`: `mipmap/sym_def_app_icon` (anydpi-v26 vector) and `drawable/sym_def_app_icon` (adaptive icon: `PackageManager.getDefaultActivityIcon`, used by Launcher3 and splash screens) |
| browser in the hotseat (Browser2, the WebView shell) | RRO `VetroBrowserOverlay`: `drawable/ic_launcher` (adaptive icon, a globe) |
| "Phone is starting…" (FallbackHome) | RRO `VetroFrameworkOverlay`: `string/android_start_title` = "Vetro is starting…" (English only); RRO `VetroSettingsOverlay`: FallbackHome's layout without the animated progress bar |
| package installer icon | RRO `VetroPackageInstallerOverlay`: `drawable/app_icon_foreground` |
| wallpaper | `/product/media/wallpaper/vetro.png` + `ro.config.wallpaper` |
| `ro.product.system.*` | `PRODUCT_SYSTEM_*` = Vetro / vetro_arm64 / "Vetro arm64" |
| still AOSP | translations of "Phone is starting…", "Android version" in Settings, "Android System" (translated into ~80 languages) |

## R2
`aosp/<version>/` with `<version>` = `<tag>-<BUILD_ID>-<vetro_rev>`: the five
images, `build-info.txt`, `SHA256SUMS`, `manifest.json` (`version`,
`base_url`, `files[]` with `path`, `size`, `sha256`) and `sources/` (GPL
sources, README). Public URL: `R2_PUBLIC_URL` + key.

## Test status (version `android-15.0.0_r36-BP1A.250505.005.D1-64fcd35`)

guest seconds; the old image `…-bd09e2f` for comparison, same QEMU and VM
(its run had adb monitoring running, top and logcat, which costs guest CPU:
the new image's run had none):

|---|---|---|
| `boot_progress_pms_ready` → `ams_ready` (first-boot dexopt) | 420 → 715 | 392 → 477 |
| `sys.boot_completed=1` | 1085 | 644 |
| user unlocked (`uc_finish_user_unlocked`) | 1211 | 696 |
| Launcher3 displayed (`wm_activity_launch_time`) | not yet at 1984 (QEMU 6.2 run: 1816) | 1552 |
| SystemUI ANR ("System UI isn't responding") | yes (1938 s) | no |
| decompressed APEXes in `/data` | 23 | 0 |
| test app's blue `#1565c0` on the scanout (QEMU `screendump`) | `#c06515` | `#1565c0`; after a touch `#ef6c00` |

## GPL
`tools/aosp/gpl-sources.sh` → `target/aosp/sources/`: `linux-<version>.tar.xz`
(kernel/common at the `-g…` commit of the kernel string), virtual-device
modules at the `scmversion` commit, `aosp/` with the archives of the
AOSP projects with `MODULE_LICENSE_*GPL*` (excluding prebuilts/, kernel/,
toolchain/), `manifest-pinned.xml`, `vetro-patches/`, `README`,
`SHA256SUMS`.

## Rebuild with a freshly started VM (ADR 0030)
From the main checkout, with this work on main (so `vetro_rev` is a
commit of main). The VM is needed only for steps 2–4 and 6.

| # | Command | Where | Estimated time |
|---|---|---|---|
| 1 | `mkdir -p target/aosp && echo vetro@<IP> > target/aosp/vm-host`; `tools/aosp/dev-ca.sh` | Mac | seconds |
| 2 | `tools/aosp/build.sh start` (check, `sync.sh`, detached build) | Mac → VM | 1–3 min |
| 3 | `tools/aosp/build.sh wait` (or `status`) | VM | 30–75 min: regeneration of Soong and Kati (Android.bp, product and host cross changed) plus conscrypt APEX, two RROs, system/product/super; towards the maximum if the VM has fewer than 16 vCPUs |
| 4 | `tools/aosp/fetch.sh` (`pack.sh` checks, ~1.6 GB via rsync, `mkdisk.sh`) | VM → Mac | 5–15 min |
| 5 | `cargo build --release -p vetro-cli` (Vetro's bootloader writes the boot files); `tools/aosp/qemu-vm.sh start` (QEMU on the VM); `tools/aosp/qemu-vm.sh adb shell ls /apex/com.android.conscrypt/cacerts/79e94fc0.0`; `… adb shell cmd overlay list` (four `vetro.overlay.*`); `… adb shell pm path com.android.quicksearchbox` (empty); `tools/aosp/qemu-vm.sh screendump target/aosp/home.png` (the scanout) and `screencap` (SurfaceFlinger); the test app `tests/apps/tocco` (`adb install`, `am start`, centre `#1565c0`) | Mac → VM | ~30 min (boot_completed ~11 min, Launcher3 ~26 min of guest time) |
| 6 | `tools/aosp/gpl-sources.sh` (kernel unchanged; GPL archives from the VM, Vetro patches updated) | Mac + VM | 5–15 min |
| — | shut down the VM | | |
| 7 | `tools/aosp/upload.sh` (new version `…-<vetro_rev>`, the previous one remains) and, after merging the browser branch, `tools/aosp/upload-web.sh` | Mac → R2 | 10–30 min depending on bandwidth |
| 8 | `tools/aosp/vetro.sh` under Vetro (long test) | Mac | ~1 h 15 min |

If the build stops on one of the two untested choices of ADR 0030
(`overrides` of QuickSearchBox on an RRO, empty host cross), just remove
the corresponding line, commit and rerun `build.sh start`: they are
independent.
