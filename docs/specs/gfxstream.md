# Spec — accelerated guest graphics: gfxstream GLES over virtio-gpu 3D, WebGL2 executor

Decision: ADR 0037. Crates: `vetro-platform` (virtio-gpu 3D, `Renderer3d`),
`vetro-gfxstream` (host decoder), `vetro-machine` (wiring, boot parameters),
`vetro-wasm` (ABI 15), `web/app/gl.mjs` (executor).

## Path of a GL call
1. The guest's `libGLESv2_emulation` encodes the call (emugen) into its
   stream; `VirtioGpuPipeStream` (`ro.boot.hardware.gltransport=virtio-gpu-pipe`)
   copies it into the 1 MiB backing of its `PIPE_BUFFER` resource and sends
   TRANSFER_TO_HOST_3D; replies are read with TRANSFER_FROM_HOST_3D + WAIT.
   One virtio-gpu context (one DRM fd) per guest GL thread.
2. `VirtioGpu` (3D only with `GpuConfig::virgl`) hands the transfer to the
   `Renderer3d`: `vetro_gfxstream::Gfxstream`.
3. The context's pipe: the first NUL-terminated bytes name the service
   (`pipe:opengles` = a render thread, `pipe:GLProcessPipe` = one int in,
   the process id `puid` out). A render thread reads 4 bytes of client flags,
   then complete calls: `u32 opcode, u32 length, parameters` (tables in
   `src/tables.rs`, generated by `tools/gfxstream/gen-tables.py` from the
   upstream specs in `crates/vetro-gfxstream/spec/`, checked against the
   upstream generated decoders for all 509 opcodes). Opcodes of GLES1
   (1024..2047) or unknown ones are skipped by length and logged.
4. `gl::Gl` answers renderControl and GLES calls: EGL objects, name
   translation, state tracking, deterministic query answers; everything that
   draws becomes ops in an `OpBuf`.
5. Ops run in batches on a `GlExecutor`: in the browser the JS executor
   (import `vetro_host.gl_execute`), natively `NullExecutor` (reads give
   zeros) or `Recorder` (writes batches for a browser replay).

A batch runs when a readback needs its results, at a present, when it
reaches 1 M words or 32 MiB of data, or at `glFinish`/`glFinishRoundTrip`.

## virtio-gpu 3D (vetro-platform)
Feature `VIRGL` (bit 0) only with `GpuConfig::virgl`; `num_capsets` = the
renderer's capsets (gfxstream: none, so minigbm accepts every format and
`VirtGpuDevice` runs without context init). Commands and errors: see the
module doc of `virtio/gpu.rs` and `docs/specs/platform.md`. 3D resources
share the 2D id space, take backing like 2D ones, can be scanouts without
backing; their content is the renderer's. Snapshots: the 3D part (resources,
contexts, the renderer's state) is written only with `virgl`, so 2D-only
machines keep their format and their key (`GpuConfig`'s `Debug` omits
`virgl` when off).

## Resources
Like upstream's `GetResourceType`: target `PIPE_BUFFER` = pipe; format R8 with
`LINEAR` bind and no sampler/render/scanout/cursor bind = plain buffer
(ignored); anything else = a ColorBuffer whose handle is the resource id.
ColorBuffer textures (`formats::tex_of_virgl`): RGBA8 for RGBA/RGBX and for
BGRA/BGRX (bytes swizzled on upload and readback: WebGL has no BGRA
textures), RGB565, R8, RG8, RGB8, RGB10_A2, RGBA16F; depth formats and YUV
exist but are not transferable in this slice. Created with LINEAR filtering
and CLAMP_TO_EDGE, like upstream.
TRANSFER_TO_HOST_3D of a ColorBuffer uploads the box (rows `stride` apart in
the backing, or width × bytes per pixel); TRANSFER_FROM_HOST_3D reads the box
back (a readback). Texture row 0 = the first row in guest memory, as
upstream; GL rendering into a window surface puts GL's y = 0 at row 0, and
presenting draws row 0 at the bottom of the screen (upstream's post).

## EGL objects (renderControl)
- Configs (`caps::CONFIGS`): RGBA8888, RGBX8888, RGB565, each without and
  with depth 24 / stencil 8, no multisampling; attributes in upstream's
  order (`CONFIG_ATTRIBS`); `rcChooseConfig` follows EGL's matching and
  sorting rules and accepts unknown attributes.
- Contexts: a share group (new or the `share` context's), a host vertex array
  standing for vertex array 0, the GL state vector (`state::GlState`).
- Window surfaces: a host framebuffer (and a depth-stencil renderbuffer if
  the config has depth or stencil) on the current ColorBuffer
  (`rcSetWindowColorBuffer` → `SurfaceAttach`); framebuffer 0 of a context
  is its draw/read surface's framebuffer. EGL's first make-current with a
  surface sets viewport and scissor to its size.
- `rcBindTexture(cb)`: the guest texture bound to TEXTURE_2D on the active
  unit becomes an alias of the ColorBuffer's texture (the EGLImage of a
  gralloc buffer); `rcBindRenderbuffer(cb)`: attachments of the current
  renderbuffer attach the ColorBuffer's texture. EGL_GL_TEXTURE_2D images
  (`rcCreateClientImage`) alias the same way through
  `glEGLImageTargetTexture2DOES`.
- Syncs are signalled at creation (execution is synchronous);
  `rcClientWaitSyncKHR` = CONDITION_SATISFIED, `glClientWaitSyncAEMU` =
  ALREADY_SIGNALED.
- A process pipe that closes destroys the contexts, surfaces and rc
  ColorBuffers created by render threads that declared its puid
  (`rcSetPuid`), like upstream's cleanup.
- Host composition (`rcCompose`…), displays, Vulkan buffers: not offered
  (−1 or 0); the image uses `hwcomposer.mode=client`.

## Host extensions and strings (caps.rs)
GL extensions: `GL_OES_EGL_image`, `GL_OES_EGL_image_external(_essl3)`,
`GL_OES_vertex_array_object`, `GL_OES_element_index_uint`,
`GL_OES_texture_npot`, `GL_OES_rgb8_rgba8`, `GL_OES_depth24`,
`GL_OES_depth_texture`, `GL_OES_packed_depth_stencil`, `GL_EXT_texture_rg`.
Host features: `ANDROID_EMU_gles_max_version_3_0`,
`ANDROID_EMU_async_frame_commands`, `ANDROID_EMU_async_unmap_buffer`. No
native sync (the guest then waits with `eglWaitClient` at swap), no
checksums, no DMA, no host composition, no Vulkan. `GL_VERSION` "OpenGL ES
3.0 Vetro". Limits: `caps::LIMITS` (GLES 3.0 minimums or common WebGL2
values; MAX_TEXTURE_SIZE 4096, 16 attributes, 16/32 texture units, 4 draw
buffers, 4 samples, no compressed formats); the Worker checks the host's
WebGL2 meets them (`WebGlExecutor.check`) before choosing this path.

## Determinism (ADR 0037, 0019)
Answered by the decoder, never by the host GPU: strings, extensions,
limits, EGL configs, `glGet*` of state (from the tracked state), compile and
link status (always success; host messages go to the host log), program
introspection (`glsl::scan` of the shader text: every declared uniform is
active, in declaration order, vertex shader first; arrays reported as
`name[0]`; structs flattened), uniform locations (virtual: consecutive per
uniform in declaration order; the executor resolves them by name), attribute
locations (explicit bindings and `layout(location)` first, then the lowest
free ones in declaration order, bound before the link), `glGetError` (the
guest tracks errors: `noHostError`), framebuffer status (COMPLETE), syncs.

Readbacks (the only host-dependent bytes the guest can see): `glReadPixels`,
`rcReadColorBuffer`, TRANSFER_FROM_HOST_3D of a ColorBuffer,
`glMapBufferRangeAEMU` with MAP_READ_BIT, `glGetQueryObjectuiv(QUERY_RESULT)`
(always 0 in WebGL: results are only available after the task ends). All go
through `Gl::flush`; recording them into the replay log (one input per
readback) is still to do (see "Missing").

## Shaders
The text given to WebGL (`glsl::rewrite_for_webgl`): `samplerExternalOES` →
`sampler2D`, the `GL_OES_EGL_image_external(_essl3)` directives removed; line
numbers kept. The guest still sees `samplerExternalOES` in introspection.

## The op stream (exec.rs ↔ web/app/gl.mjs)
u32 words, `code << 16 | words`, floats as bits; bulk data in a blob
referenced by (offset, length), 8-aligned. Codes: `exec::CODES`, exported to
`web/app/gl-ops.mjs` (a test fails if it is stale:
`VETRO_UPDATE_GL_OPS=1 cargo test -p vetro-gfxstream`). Host object ids are
global; the executor keeps them in one array. Client-side vertex data and
inline indices use the executor's scratch buffers and name the binding to
restore. Helper ops (`TexAlloc`, `TexUpload`, `ReadTexture`,
`SurfaceAttach`, `Present`) save and restore every binding and pixel-store
value they touch.

All guest contexts share the executor's one WebGL2 context: when a render
thread whose context is not the active one sends a call,
`state::transition` emits only the state that differs.

## In the page (vetro-wasm ABI 15, web/app)
`DEV.GPU_3D` (64) gives the GPU virgl; `vetro_gl_enable` installs the JS
executor; `vetro_gl_stats`, `vetro_gl_take_log`; `vetro_display_is_3d`,
`vetro_display_read_3d` (host readback of the scanout for the home-screen
detector and screenshots: rows from the top). `?gpu=webgl` (Android only):
the Worker creates `WebGlExecutor` on an `OffscreenCanvas`, adds
`GFXSTREAM_PARAMS` to the boot parameters, turns snapshots off, and sends
presented frames as ImageBitmaps (`frame3d`); `drawBitmap` on both
presenters. Without WebGL2 (or below the limits) it falls back to
SwiftShader and says why (`gpu` message, `vetroState.gpu`).

## Snapshots (snapshot.rs)
Written only by a machine whose GPU has virgl (the 2D format is unchanged).
Data: the pipes (service state, pending input, unread replies, the render
thread's current context and surfaces), resources, scanouts, puids, and the
whole `Gl` (names, shaders with their text, programs with their link results
and uniform values, per-context state vectors, vertex array and framebuffer
records, texture/renderbuffer/sampler specifications, surfaces, ColorBuffers,
images, owners). Contents read back at save time, in one batch through the
executor (`ReadTexture` for ColorBuffers, `ReadTextureLevel` as RGBA8 for 2D
and cube levels of 8-bit unsigned formats, `ReadBufferData` for buffers),
compressed. A restore sends `ResetAll`, recreates every object under its old
id (textures with their levels and parameters, buffers with `BufferUpload`,
renderbuffer storage, samplers, shaders compiled, programs relinked with the
same attribute locations and uniform values, framebuffer attachments,
vertex arrays, surfaces), uploads the contents, then `ResetState`; the first
call of each context applies its state vector again. Not restored: depth and
stencil contents, renderbuffer contents, float or packed-format texture
contents, 3D and array texture contents, queries, transform feedback.
Readbacks at save time are host reads (like screenshots), not guest inputs.
In the page the Worker still turns snapshots off on this path until the
snapshot key and the prebuilt snapshot (ADR 0031) cover it.

## Natively
`vetro boot --gpu=gfxstream [--gl-record=FILE] [--gl-trace=1]`: virgl GPU,
the boot parameters, `vetro-gl:` log lines on stderr (with `--gl-trace=1`
every call and pipe event), counters at exit; the recording replays in
Chrome with `node tests/web/gl.mjs --recording=FILE`.

## Tests
- `cargo test -p vetro-platform gpu`: virtio-gpu 3D (features, capsets,
  contexts, resources, transfers, submit, 3D scanouts, snapshot, 2D
  unchanged).
- `cargo test -p vetro-gfxstream`: wire format, tables, configs, state
  transitions, GLSL scanning, pipes and renderControl, a window surface and a
  program, BGRA transfers, context switches, the synthetic scene.
- `node tests/web/gl.mjs`: the synthetic scene on Chrome's SwiftShader WebGL2
  must equal the expected image exactly; then a snapshot with GPU resources:
  phase A replays the scene and the save's readback batch in WebGL2, phase B
  (`examples/snapshot.rs`) saves with those bytes, restores into a new
  renderer and lets the guest redraw with its old program, texture alias and
  vertex array; replayed on a fresh WebGL2 context the window must equal the
  expected image.

## Missing (next slices)

composition, compressed textures (ETC2),
YUV buffers, program binaries, transform feedback varyings, uniform block
data sizes beyond a bound, Vulkan (gfxstream Vulkan → WebGPU, separate ADR).
