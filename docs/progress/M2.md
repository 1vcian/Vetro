# M2 — progress log

## 2026-09-24
- **Done:**
  - Linux user mode layer in `vetro-cli`. It contains:
    - tasks and a deterministic scheduler, blocking syscalls re-executed;
    - signals with arm64 `rt_sigframe`, virtual time, virtual `/proc`;
    - sysroot like `qemu -L`, MAP_SHARED, lazy memory;
    - POSIX locks, SysV shm, in-kernel FIFOs, futexes shared between processes.
  - SIMD and floating point, verified against QEMU with dedicated generators.
  - Cortex-A53 cryptographic extensions: AES, SHA1, SHA256.
  - `vetro run --strace`: syscall tracer in strace format.
  - Static BusyBox: 30 cases identical to native QEMU, with the same environment
    and the same guest variables.
  - RISU as apprentice on Vetro, with QEMU as master: identical. It
    found a decoder bug (ADR 0006).
- **Problems found along the way:**
  - The BusyBox comparison was not fair: PATH and `{wd}` were missing, and native
    QEMU passed HOME to the guest.
  - Lazy memory introduced a regression: `iovec {NULL, 0}`
    returned EFAULT.
  - A host FIFO blocked an LTP run for hours; for this reason FIFOs
    are now emulated and there is a time limit for each case.

## 2026-09-25
- **Done:** LTP on an arm64 Linux host, the same environment as the CI linux
  job. The first round gave 110 identical tests out of 356. Now, in the container on
  macOS, it is 352 out of 355: the three remaining are timing tests that in the
  Docker Desktop VM fail natively too.
  - Emulated kernel, new syscalls and commands:
    - capget/capset, personality (UNAME26);
    - rt_sigtimedwait, futex_waitv;
    - SIGIO with F_SETOWN(_EX)/F_SETSIG;
    - leases, OFD locks, deadlock in F_SETLKW;
    - F_GET/SETPIPE_SZ, F_CREATED_QUERY, FIONREAD;
    - O_PATH, O_TMPFILE, SEEK_DATA/SEEK_HOLE;
    - `/proc/<pid>/{fd,task,pagemap}`, magic links `/proc/<pid>/fd/N`.
  - Emulated kernel, memory:
    - `mremap` preserves shared memory;
    - MAP_GROWSDOWN and SIGBUS past the end of a mapped file;
    - MAP_SHARED_VALIDATE, VM_MAYWRITE, TASK_SIZE;
    - coherence between descriptors and MAP_SHARED.
  - Emulated kernel, process state:
    - per-process rlimit;
    - guest umask applied exactly, canonical cwd;
    - host errno translated by name (on Linux the numbers stay the same).
  - Real bugs:
    - the signal trampoline was not mapped and lived inside the stack;
    - alarms were not delivered if all tasks were blocked;
    - the lock order was wrong;
    - `open(O_RDONLY|O_CREAT)` failed because of a `std` limitation.
  - Performance: the next alarm deadline is cached. Previously the
    tasks were scanned at every instruction; with many threads it is 4 times
    faster.
  - Virtual time: 10 ns per instruction and 1 µs per syscall (ADR 0010).
  - LTP harness (ADR 0010):
    - kernel version and CPU taken from the oracle;
    - native oracle for tests where QEMU is wrong
      (`tools/ltp/qemu-divergent.txt`, each entry verified native/QEMU);
    - oracle repeated if it diverges;
    - timing tests run on their own (`tools/ltp/timing.txt`);
    - QEMU outcome read from the exit code;
    - oracle descriptor limit unchanged.
- **Problems found along the way:**
  - In the container on macOS, bind mounts (virtiofs) change permissions and
    locks, and QEMU fails tests that pass on ext4. Trial runs use
    an ext4 volume for `target/tmp`, like the CI.
  - Some SIGSEGVs attributed to QEMU were children of the test that were supposed to
    die.
- **Exit criterion:** green in GitHub CI, run 36109015705, linux job
  on a real arm64 host. All 355 LTP tests in the selection have the same
  outcome as the oracle: QEMU, or native for `qemu-divergent.txt`, timing
  tests included. BusyBox (30 cases) and RISU are green too.
  `fork14` is excluded with a reason.
- **Missing:** nothing for the criterion. The syscall tracer covers the
  most common syscalls; missing names are added as they come up.
- **Blocked:** nothing.
- **Next (M3):** connect the system mode CPU, MMU and platform, already
  ready and tested separately, and boot the guest kernel comparing it against
  `qemu-system-aarch64`.
