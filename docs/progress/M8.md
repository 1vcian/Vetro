# M8 — progress log

## 2026-09-26 (file manager foundation on the Linux guest, Web agent)
- **Done:** file manager (ADR 0020, `docs/specs/files.md`): `vetro-files` daemon in static C in the initramfs (started by `/init` if virtio-vsock is present, port 5200) with list/stat (mode, uid/gid, mtime, target, `security.selinux` context), chunked reads, atomic write (temporary file in the same folder + rename, owner, mode and xattrs preserved; new files with the folder's owner and context), create/mkdir/delete/rename, watch with inotify; guest kernel with `INOTIFY_USER` and `TMPFS_XATTR`; dependency-free Rust client in `vetro_machine::files` (only `Machine::input` and `vsock_view`: sessions recorded and replayed identically), vetro-wasm ABI 7 (`vetro_files_*`), `GuestFiles` in `web/node/vetro.mjs`, `vetro boot --files-ls/--files-cat/--files-put`; panel in the web app next to the screen (roots set by the caller, live tree, text/JSON/XML viewers with SharedPreferences/hex/images/SQLite with our own format reader, editing and saving in the guest). Green tests: unit (protocol, client with a fake daemon, JSON, SQLite on a real database), `tests/boot` (`files.rs`: metadata, 1.2 MB in chunks, mode/owner/xattrs preserved as read from the guest, event from a guest process after 40 ms of guest time, two identical runs, record & replay; `snapshot.rs`: cuts in the middle of a session), `vetro-cli` (`boot_files.rs`), Node (`tests/web/files.mjs`) and Chrome (`browser.mjs`: file edited in the panel and re-read from the guest with `cat`, reconnection after the snapshot restore).
- **Missing:** detection of the foreground app from the Binder decoder (ActivityTaskManager) to set the roots (`app_roots`); daemon in the Android image (init service, SELinux policy, bionic); editing an SQLite row (M8 exit: needs `sqlite3` in the guest or in the daemon, with an ADR); reading SQLite's WAL; structured editing of SharedPreferences (today via the XML text); non-UTF-8 file names.
- **Blocked:** the M8 exit waits for Android (M5) and the Binder decoder; comparing virtio-vsock with QEMU remains impossible in Docker Desktop and on the runners (no `/dev/vhost-vsock`, see M5).

## 2026-09-26 — Binder decoder and privacy inspector (Analysis agent, ADR 0029)
- **Done:** decoding of raw Binder transactions (ADR 0027).
  `tools/aosp/aidl-map.sh` extracts the system partition from `super.img`
  (EROFS with `fsck.erofs`) and reads with `dexdump` the constants of the AIDL
  stubs (`TRANSACTION_*`, IContentProvider's `*_TRANSACTION`): a map
  descriptor+code → method of the running image (`aidl_aosp15.tsv`,
  1306 interfaces, 11637 methods; IActivityManager, IPackageManager,
  ILocationManager, ITelephony, IContentProvider, IClipboard,
  ICameraService, ...). `vetro_analysis::introspect`: `parcel`
  (`writeInterfaceToken` header, String16), `aidl` (map +
  IBinder's reserved codes), `ipc::{BinderCall, BinderLog}` (pairs the
  sender's BC and the receiver's BR by code and Parcel bytes;
  sender/receiver with pid, uid, package from the process name),
  `privacy` (clipboard, ANDROID_ID and other identifiers such as IMEI/IMSI/
  ICCID/serial, location, contacts/call log/sms/calendar, camera,
  microphone, accounts, installed apps). `vetro_machine::analysis::BinderTracer`
  on EL0 `ioctl(BINDER_WRITE_READ)`. `vetro boot --binder-log=FILE`
  (JSON or lines; sensitive accesses on stderr). Tests: unit (Parcel,
  AIDL map, the two halves, ANDROID_ID and clipboard as sensitive), `vetro boot
  --binder-log` on the test kernel (no crash, 0 calls without Binder).
- **Missing:** long test on Android from a snapshot (`VETRO_ANDROID=1`):
  listing system_server's transactions on the home screen and the test app
  (`tests/apps/vetro-probe`) reading the clipboard and ANDROID_ID as sensitive
  accesses — not done yet (needs the snapshot at boot_completed).
  Method names of native-only interfaces (C++/NDK, HAL) and of jars
  in APEXes (outside /system/framework).
