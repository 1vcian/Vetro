# M8 — diario

## 2026-09-26 (base del gestore dei file sul guest Linux, agente Web)
- **Fatto:** gestore dei file (ADR 0020, `docs/specs/files.md`): demone `vetro-files` in C statico nell'initramfs (avviato da `/init` se c'è virtio-vsock, porta 5200) con list/stat (modo, uid/gid, mtime, destinazione, contesto `security.selinux`), letture a pezzi, scrittura atomica (temporaneo nella stessa cartella + rename, proprietario, modo e xattr conservati; file nuovi con proprietario e contesto della cartella), create/mkdir/delete/rename, watch con inotify; kernel guest con `INOTIFY_USER` e `TMPFS_XATTR`; client Rust senza dipendenze in `vetro_machine::files` (solo `Machine::input` e `vsock_view`: sessioni registrate e rigiocate identiche), vetro-wasm ABI 7 (`vetro_files_*`), `GuestFiles` in `web/node/vetro.mjs`, `vetro boot --files-ls/--files-cat/--files-put`; pannello nell'app web accanto allo schermo (radici impostate dal chiamante, albero dal vivo, visualizzatori testo/JSON/XML con SharedPreferences/esadecimale/immagini/SQLite con lettore del formato nostro, modifica e salvataggio nel guest). Test verdi: unitari (protocollo, client con demone finto, JSON, SQLite su un database vero), `tests/boot` (`files.rs`: metadati, 1,2 MB a pezzi, modo/proprietario/xattr conservati letti dal guest, evento di un processo del guest dopo 40 ms di tempo del guest, due esecuzioni uguali, record & replay; `snapshot.rs`: tagli a metà sessione), `vetro-cli` (`boot_files.rs`), Node (`tests/web/files.mjs`) e Chrome (`browser.mjs`: file modificato nel pannello e riletto dal guest con `cat`, ricollegamento dopo il ripristino dello snapshot).
- **Manca:** rilevamento dell'app in primo piano dal decoder Binder (ActivityTaskManager) che imposti le radici (`app_roots`); demone nell'immagine Android (servizio di init, policy SELinux, bionic); modifica di una riga SQLite (uscita di M8: serve `sqlite3` nel guest o nel demone, con un ADR); lettura del WAL di SQLite; modifica strutturata delle SharedPreferences (oggi dal testo XML); nomi di file non UTF-8.
- **Bloccato:** l'uscita di M8 aspetta Android (M5) e il decoder Binder; il confronto di virtio-vsock con QEMU resta impossibile in Docker Desktop e sui runner (manca `/dev/vhost-vsock`, vedi M5).
